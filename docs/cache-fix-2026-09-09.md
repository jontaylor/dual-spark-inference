# GB10 recurrent-cache fix — 2026-09-09

Fixed sparse recurrent-state reclamation during asynchronous chunked prefill, corrected prefill alignment, and included outstanding state copies in the startup capacity estimate.

## Deployment

Official `Qwen/Qwen3.8-Flash-Next-FP8`, BF16 KV, TP2 + EP + MTP3, C4, 262,144 total tokens/request and an 8,192-token scheduling budget. Memory utilisation remains 0.76. The endpoint, credential and mmap FP8 PLE path are preserved.

## Changes

- Mamba align cleanup traverses null gaps while retaining the existing committed-token fence. It releases obsolete checkpoints without releasing states still needed by an outstanding batch or another request.
- Prefill splitting uses the resolved 1,600-token scheduler alignment instead of the indexer ring’s 8-token size.
- The capacity estimate budgets each extra outstanding batch’s state copy. With MTP3 and two overlapping batches, the modelled peak is 189 pool blocks/request, versus the old estimate of 185.
- Optional cache-group accounting logs pool occupancy and per-request block ownership every two seconds, without prompt contents.

## Correctness and reproducibility

- Each node passed 12 metadata context cases plus ownership/fence, copy-on-write retention and preemption/reuse checks. Cases include MTP on/off, fine-grained hashing and up to three outstanding batches.
- The original allocator fails the new sparse-state regression. Corrected C4 metadata peaks at 756 blocks, with 724 during decode.
- API smoke and 11 existing functional checks passed.
- Cold, cached and follow-up-turn outputs matched in the 12K and 65K checks; cache reuse was confirmed by prefix-hit counters. Log-probability differences are retained in the summary JSON. This is bounded numerical regression evidence, not exhaustive equivalence across all workloads.
- Overlay generators reproduce the deployed sources, and source hashes match both nodes.
